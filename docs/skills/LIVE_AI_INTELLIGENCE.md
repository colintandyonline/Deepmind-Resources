# Live AI Intelligence Skill

This skill defines the rules for the DeepMindResources Live AI Intelligence system.

The Live AI Intelligence system tracks important AI changes, validates what matters, and turns verified updates into practical learning actions.

---

## Core Purpose

The Live AI Intelligence system exists because AI moves too quickly for normal courses to stay current.

Its job is not to publish AI news for the sake of news.

Its job is to detect meaningful AI changes and translate them into:

- Verified explanations
- Tool intelligence
- Lesson updates
- New lessons
- Sandbox tasks
- Tool comparison updates
- Business training implications

---

## Product Promise Connection

Every Live AI Intelligence item should support the product loop:

AI update → verified meaning → practical lesson → sandbox task → user skill gain

If an update cannot be connected to learning value, tool choice, sandbox practice, or business usefulness, it should usually be filtered out or downgraded.

---

## Update Categories

The system should track important changes in these categories:

- New model releases
- Model capability changes
- API changes
- Pricing changes
- Platform updates
- Tool launches
- Tool deprecations
- Feature removals
- New AI coding assistants
- New automation tools
- New agent frameworks
- RAG and knowledge-system updates
- Safety and policy changes
- Benchmark or evaluation changes
- Business AI workflow changes
- Major documentation updates

---

## Required Questions for Every Update

Every useful update should answer:

1. What changed?
2. Who announced it or where was it found?
3. Is the source official or trusted?
4. Why does it matter?
5. Who should care?
6. What skill does this affect?
7. What tool, model, platform, or workflow is affected?
8. Is this update verified?
9. What confidence score should it have?
10. Should an existing lesson be updated?
11. Should a new lesson be created?
12. Should a sandbox task be created?
13. Should a tool comparison be updated?
14. Does this affect business training or tool-buying decisions?

---

## Feed Item Structure

A Live AI Intelligence feed item should include:

- Title
- Short summary
- Update category
- Source reference
- Source quality level
- Confidence score
- Date detected
- Date checked
- Practical meaning
- Affected user level
- Affected skill area
- Affected tool/model/platform
- Lesson action
- Sandbox action
- Tool comparison action
- Business training action
- Publication status

---

## Update Statuses

Each update should have a clear status.

Suggested statuses:

- Signal detected
- Awaiting validation
- Needs source check
- Verified
- Rejected as noise
- Conflicting evidence
- Lesson update pending
- Sandbox task pending
- Tool comparison update pending
- Published
- Archived

Do not treat detected signals as verified updates.

---

## Source Standards

Live AI Intelligence should prefer:

- Official documentation
- Official release notes
- Official changelogs
- Official product blogs
- Official GitHub repositories
- Direct testing
- Trusted technical analysis

Low-quality sources can be used as early discovery signals, but they should be marked as unverified.

Avoid publishing updates based only on:

- Viral social posts
- Affiliate blogs
- Shallow tool review pages
- Unsourced claims
- AI-generated comparison content
- Marketing hype with no technical detail

---

## Practical Meaning Requirement

Every published update should explain practical meaning.

Bad update style:

- A new model has launched.
- A tool has added AI features.
- A platform says it is faster.

Good update style:

- What changed in the model or platform.
- What this means for learners.
- Which workflows are affected.
- Which lessons may need updating.
- What users can practise in the sandbox.
- Whether businesses should change tool decisions.

## Lesson Action Rules

A Live AI Intelligence item may create a lesson action.

Lesson action values:

- No lesson action needed
- Update existing lesson
- Create new beginner lesson
- Create new intermediate lesson
- Create new advanced lesson
- Create business training note
- Review existing lesson for outdated information

A lesson should only be updated when the change affects practical understanding or skill development.

---

## Sandbox Action Rules

A Live AI Intelligence item may create a sandbox action.

Sandbox action values:

- No sandbox action needed
- Create prompt test
- Create model comparison task
- Create tool-calling exercise
- Create agent-building task
- Create RAG exercise
- Create debugging task
- Create business workflow simulation
- Create validation challenge

Sandbox tasks should be hands-on and testable.

---

## Tool Comparison Action Rules

A Live AI Intelligence item may affect tool comparison pages.

Comparison action values:

- No comparison action needed
- Update capability table
- Update pricing note
- Update use-case recommendation
- Add limitation
- Add new tool
- Mark tool as deprecated
- Recheck previous ranking

Tool comparison updates must remain use-case based.

Do not crown a tool as universally best.

---

## Business Training Action Rules

A Live AI Intelligence item may affect business training.

Business action values:

- No business action needed
- Add staff training note
- Update business workflow lesson
- Update tool-spend recommendation
- Add risk or privacy note
- Add non-technical staff guidance
- Add team implementation note

Business-facing changes need extra caution because they can affect tool spend, staff training, security, and process decisions.

---

## Queue Rules

The Live AI Intelligence queue should separate different stages of work.

Suggested queues:

- Detected signals
- Needs validation
- Verified updates
- Master Brain queue
- Lesson updates pending
- Sandbox tasks pending
- Tool comparison updates pending
- Business training updates pending
- Rejected noise

The homepage should eventually show a simplified, user-friendly version of these queues.

Internal queue data can be more detailed.

---

## Agent Responsibilities

### Scout Agent

Finds signals from official sources, docs, changelogs, repositories, and trusted AI news sources.

### Noise Filter Agent

Removes or downgrades low-value hype before it pollutes the intelligence queue.

### Validator Agent

Checks sources, confidence, and evidence.

### Tool Agent

Maps updates to tool capabilities, limitations, pricing, and categories.

### Use-Case Agent

Maps updates to practical scenarios and users.

### Comparison Agent

Updates tool comparison implications.

### Lesson Builder Agent

Suggests lesson updates or new lessons.

### Sandbox Builder Agent

Suggests practice tasks.

### Business Training Agent

Maps updates to workplace training implications.

---

## Public Feed Rules

The public Live AI Intelligence feed should be useful, not overwhelming.

Do not show raw noise.

Public feed items should be:

- Verified or clearly labelled as under review
- Plain-English
- Practical
- Connected to a skill or use case
- Free from hype
- Linked to lessons or sandbox tasks where possible

The public feed should not become a generic AI news feed.

---

## Internal Feed Rules

The internal feed can include unverified signals, but they must be labelled clearly.

Internal records should preserve:

- Original source
- Detection date
- Claim summary
- Status
- Confidence
- Assigned agent or workflow
- Notes on why the signal matters or does not matter

---

## Definition of Done

A Live AI Intelligence item is complete when it has:

- Clear update summary
- Source reference
- Source quality level
- Validation status
- Confidence score
- Practical meaning
- Affected audience
- Affected skill area
- Lesson action
- Sandbox action
- Tool comparison action
- Business training action
- Publication decision

---

## Locked Rule

DeepMindResources does not chase AI news.

It converts verified AI change into practical learning intelligence.
