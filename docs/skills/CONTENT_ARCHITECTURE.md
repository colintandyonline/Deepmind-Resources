# Content Architecture Skill

This skill defines how DeepMindResources should organise pages, lessons, learning paths, tool intelligence, AI updates, sandbox tasks, business training content, internal links, public routes, and future content workflows.

Content architecture prevents the platform from becoming a messy collection of disconnected pages.

It is the system that keeps DeepMindResources growing like a structured AI learning and intelligence platform, not a random blog, generic course site, or loose dashboard app.

---

## Core Purpose

DeepMindResources is a living AI training and tool-intelligence platform.

Its content should guide users from:

- Discovery
- Understanding
- Tool selection
- Lesson learning
- Sandbox practice
- Skill progress
- Business training
- Current AI updates
- Verified AI intelligence

The content structure must support the product loop:

AI update → verified meaning → practical lesson → sandbox task → user skill gain

For business users, this becomes:

AI update → verified business meaning → staff training → workflow practice → team capability gain

---

## Core Rule

Every public page, lesson, tool page, update page, sandbox task, and business training resource must have a clear place in the platform.

Do not create orphan pages.

Do not create pages with duplicate search intent.

Do not create content without knowing which user journey, skill, pillar, or business outcome it supports.

Every content item needs:

- A purpose
- A pillar
- An audience
- A search intent where public
- A relationship to other platform content
- A next action for the user

---

## Main Content Pillars

DeepMindResources content should be organised around these pillars:

1. Academy
2. Agentic Sandbox
3. Live AI Intelligence
4. Tool Intelligence and Comparison
5. Master Brain / verified knowledge layer
6. Business AI Training
7. Progress and skill tracking
8. Trust, validation, and methodology

Each major page or feature should support at least one pillar.

If a page does not clearly support a pillar, it should not be built yet.

## Academy Architecture

The Academy should contain structured learning paths, not loose lessons.

Academy content should be organised into:

- Learning paths
- Modules
- Lessons
- Practice tasks
- Assessments where useful
- Related tool comparisons where useful
- Related Live AI Intelligence updates where useful

Core learning areas include:

- AI Fundamentals
- Prompt Engineering
- AI Tool Selection
- AI for Business Productivity
- Tool Calling and Functions
- AI Agents
- RAG and Knowledge Systems
- Agentic Workflows
- Multi-Agent Systems
- AI Safety, Validation, and Hallucination Control

Lessons should connect to sandbox tasks whenever practical.

Lessons should not float alone unless there is a clear reason.

---

## Learning Path Rules

Each learning path should have:

- Clear title
- Clear audience
- Skill level
- Learning outcome
- Ordered modules or lessons
- Related sandbox tasks
- Estimated duration where useful
- Progress logic
- Related business version where applicable
- SEO metadata if public

Learning paths should move users from understanding to application.

A learning path should not be a random list of lessons.

---

## Lesson Content Rules

Each lesson should belong to:

- A learning path or skill area
- A difficulty level
- A target audience
- One or more related sandbox tasks where useful
- One or more related Master Brain records where relevant

Each lesson should answer:

- What does this teach?
- Who is it for?
- Why does it matter?
- What should the learner know by the end?
- What should the learner be able to do by the end?
- What should the learner do next?

Lessons should include practical examples and should avoid generic AI filler.

## Tool Detail Page Rules

A tool detail page should explain:

- What the tool is
- What it is best suited for
- Who should use it
- Who should avoid it
- Key capabilities
- Key limitations
- Pricing or plan caveats where verified
- Related tools
- Related comparisons
- Related lessons
- Related sandbox tasks
- Date checked where claims are time-sensitive

Tool pages should not copy marketing claims as facts.

---

## Tool Comparison Page Rules

A tool comparison page should have:

- Clear comparison use case
- Defined audience
- Tools compared
- Short answer summary
- Comparison table
- Strengths and limitations
- Pricing or plan caveats
- Evidence or validation note
- Related lessons
- Related sandbox tasks
- FAQ section where useful

Avoid universal rankings like “best AI tool overall”.

Use scenario-based comparisons such as “best AI tool for coding”, “ChatGPT vs Claude for writing”, or “n8n vs Zapier for automation”.

## Content Lifecycle Rules

Content should have lifecycle states.

Suggested states:

- Draft
- In review
- Needs validation
- Verified
- Published
- Needs update
- Deprecated
- Archived

AI content changes quickly, so lifecycle status matters.

Live AI Intelligence and Master Brain records should be able to trigger content refreshes.

## Public vs Internal Content

Not all content should be public.

Internal content may include:

- Unverified signals
- Agent findings
- Raw source summaries
- Validation notes
- Draft recommendations
- Conflicting evidence
- Internal review notes

Public content should be verified, useful, and clearly written.

---

## Avoiding Content Sprawl

Before creating new content, ask:

1. Does this support a core pillar?
2. Does this duplicate an existing page?
3. What search intent does it serve?
4. Which audience is it for?
5. Which skill does it teach or support?
6. Does it link to related lessons or tasks?
7. Does it need source validation?
8. Does it belong in the Master Brain first?
9. Does it have a clear next action?
10. Is it useful enough to exist?

If the answers are unclear, do not create the page yet.

## SEO and AI Search Alignment

Public content should follow the SEO and AI Search skill.

Each public page should have:

- Clear search intent
- Unique metadata
- One H1
- Useful summary near the top
- Logical headings
- Human-readable explanations
- LLM-readable structure
- Internal links
- Clear next step

Content architecture and SEO should work together.

---

## Data Model Alignment

Content architecture should align with the data model.

Public and internal records should connect through structured relationships where possible.

Examples:

- AI update → source records
- AI update → Master Brain record
- Master Brain record → lesson update
- Lesson → sandbox task
- Tool capability → tool comparison
- Tool comparison → business training page
- User progress → learning path

Relationships are what allow the platform to become intelligent over time.

---

## Definition of Done

Content architecture is healthy when:

- Every page belongs to a pillar
- Every lesson belongs to a path or skill area
- Every sandbox task practises a defined skill
- Every tool comparison has a clear use case
- Every AI update has validation status
- Every public page has clear search intent
- Internal links guide users forward
- No major content is orphaned
- Duplicate intent is avoided
- Public and internal content are separated correctly
- Content lifecycle status is clear

DeepMindResources should grow like a structured intelligence platform, not like a random blog.

Every content item needs a purpose, a place, a relationship, and a next action.
